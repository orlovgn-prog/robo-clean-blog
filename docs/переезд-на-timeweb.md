# Переезд maddroidblog.ru с Vercel на Timeweb

Сайт статический, поэтому переносится как папка файлов. Сборку берёт на себя
GitHub Actions (`.github/workflows/deploy.yml`): на каждый push собирает Astro
и заливает `dist` по FTPS, только изменившиеся файлы.

Порядок важен: **сначала выкладываем файлы, потом переключаем домен.** Тогда
переезд проходит без простоя и в любой момент откатывается.

## Что уже сделано в репозитории

- `.github/workflows/deploy.yml` — сборка и выкладка
- `public/.htaccess` — HTTPS-редирект, 404, кэширование; Astro копирует его в `dist`

## Шаг 1. Завести сайт на Timeweb

В панели добавить домен `maddroidblog.ru` как новый сайт.

**Определить боевой корень — меткой, а не догадкой.** На termobags.ru корнем
оказался `~/public_html`, хотя панель создала и `~/termobags.ru/public_html`,
который доменом не обслуживался. Из-за такой догадки на боевой сайт однажды
уехал `robots.txt` с `Disallow: /`.

Для второго сайта на том же аккаунте структура, скорее всего, будет другой —
поэтому проверить:

1. Положить в предполагаемый корень файл `marker.txt` со словом `here`.
2. Открыть `http://maddroidblog.ru/marker.txt` (или временный адрес, который
   выдаёт Timeweb, пока домен ещё смотрит на Vercel).
3. Слово видно — корень найден. Не видно — пробовать следующий каталог.
4. Метку потом удалить.

Найденный путь понадобится на шаге 2 как `FTP_SERVER_DIR`.

## Шаг 2. Прописать доступы в GitHub

`Settings → Secrets and variables → Actions`

**Secrets** (значения не показывать никому, в том числе в чате):

| Имя | Что это |
|---|---|
| `FTP_SERVER` | хост FTP из панели Timeweb |
| `FTP_USERNAME` | логин FTP |
| `FTP_PASSWORD` | пароль FTP |

**Variables:**

| Имя | Пример |
|---|---|
| `FTP_SERVER_DIR` | `/public_html/` — путь с шага 1, обязательно со слешем на конце |

Если переменная не задана, workflow падает сразу с понятной ошибкой и ничего
не заливает — это защита от выкладки мимо сайта.

## Шаг 3. Первая выкладка (домен ещё на Vercel)

`Actions → Deploy to Timeweb → Run workflow`

Workflow соберёт сайт и зальёт его. Проверить по временному адресу Timeweb:
открывается главная, работают статьи, поиск, картинки.

Если FTPS не поднимется, в `deploy.yml` поменять `protocol: ftps` на `ftp`.

## Шаг 4. Переключить домен

Домен у reg.ru, NS там же (`ns1/ns2.reg.ru`) — **NS менять не нужно**.
Меняется только A-запись:

- было: `216.198.79.1` (Vercel)
- станет: IP сервера Timeweb (в панели; у termobags.ru это `92.53.96.169`)

Почты на домене нет, поэтому MX-записи не при чём и риска потерять письма —
в отличие от termobags.ru — здесь нет.

Обновление занимает от нескольких минут до пары часов.

## Шаг 5. Сертификат

Когда домен начнёт резолвиться на Timeweb — выпустить Let's Encrypt в панели.

В `.htaccess` путь `.well-known/acme-challenge/` уже исключён из редиректа на
HTTPS: без этого выпуск и продление зацикливаются. Workflow этот каталог не
трогает (он в списке исключений), так что выкладки его не сотрут.

## Шаг 6. Отключить Vercel

Только после того, как сайт открывается с Timeweb по https и всё работает:
убрать домен из проекта на Vercel, чтобы два хостинга не спорили за него.
Сам проект можно оставить — как быстрый откат.

## Что при этом не меняется

Автосбор новостей в n8n трогать не нужно вообще: он коммитит `.md` в GitHub,
а репозиторий остаётся прежним. Меняется только то, кто собирает и выкладывает
сайт после коммита.

Единственная разница — время появления статьи: у Vercel было около 15 секунд,
через GitHub Actions будет пара минут (установка зависимостей, сборка, заливка).
